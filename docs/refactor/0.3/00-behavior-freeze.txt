TORCA 0.3 BEHAVIOR FREEZE
=========================

BATCH: 0.3.0
BASE COMMIT: 604708230b2ed84ba3c71cf05651af2a2648a712
PURPOSE: protect observable 0.2 behavior while ownership and implementation are
moved between frontend and backend.

STATUS LEGEND
-------------

COVERED       existing automated test identified
PARTIAL       some automated coverage exists, additional scenario required
MANUAL        release evidence currently required
GAP           no adequate test identified; must be added before old path removal

GENERAL INVARIANTS
------------------

1. One user intention produces at most one durable domain mutation.
2. Replaying the same durable command_id returns the same logical result.
3. Reusing a command_id with a different payload is rejected.
4. A network failure never rolls back an already committed user intention.
5. An event is never published before the corresponding durable commit.
6. Restart recovery never creates duplicate contacts, conversations or messages.
7. Flutter never becomes authoritative for pairing, delivery or relationship state.
8. Normal messages never use rendezvous relay forwarding.
9. Raw SQL remains in torchat-storage.
10. Secrets and message plaintext do not appear in diagnostics or normal logs.

BATCH ACCEPTANCE RULE
---------------------

A refactor batch may remove an old implementation only when:
- the relevant behavior above is COVERED or a new test is added;
- GAP scenarios affected by the batch are implemented before removal;
- tests not executed are recorded in the batch report;
- no alternate compatibility implementation remains.
