# Torca 0.2.0-beta.1

Build: `2`  
Channel: `beta`  
Compatibility: `rollback-compatible only after the recorded upgrade/rollback test`

## Purpose

This is a closed test release for Windows and Android. Its purpose is to
validate pairing, direct onion P2P messaging, persistence, platform lifecycle,
upgrade behaviour and support tooling with a controlled tester group.

It is not a claim of complete anonymity or production security. Compromised
devices, operating-system compromise, global traffic analysis and Tor network
vulnerabilities remain outside the protection boundary.

## Included

- local installation identity and profile;
- short-lived code and QR pairing with explicit approval;
- private contacts and one-to-one conversations;
- text messages, replies and bounded image attachments;
- durable delivery retry, delivery receipts and optional read receipts;
- direct authenticated onion peer delivery;
- presence, typing and conversation-focus signals;
- relationship removal and re-pairing;
- Windows tray/autostart integration;
- Android foreground/background lifecycle integration;
- local sanitized diagnostic export;
- local destructive profile reset with two-stage confirmation;
- signed offline update-manifest verification;
- Polish and English interface support.

## Not included

- groups;
- calls;
- iOS;
- public user discovery;
- multi-device synchronization;
- cloud backup;
- automatic diagnostic upload;
- automatic update installation;
- official Linux or macOS clients.

## Tester requirements

- Install only artifacts supplied with matching SHA-256 checksums.
- Keep both devices available during pairing; the relay has no offline mailbox.
- Copy release information before reporting a problem.
- Export sanitized diagnostics before resetting a profile.
- Never share pairing codes, private keys, message plaintext or profile files.
- Report every stuck pairing, silent message loss, duplicate contact, unexpected
  identity change or upgrade failure immediately.

## Update verification

Settings can verify a local `torca-update-manifest.json`. Verification checks the
embedded key identifier, Ed25519 signature, semantic version/build and artifact
SHA-256 metadata. Torca 0.2 does not automatically fetch or install the artifact.

## Known limitations

- Tor bootstrap and onion reachability can take longer than ordinary internet
  messaging applications.
- Android background restrictions can delay availability and may require user
  action in system settings.
- A Windows installer is assembled separately from the validated Windows
  release bundle; its contents must remain byte-identical to that bundle.
- Diagnostic export is deliberately minimal and privacy-first.
- Image attachments are limited to static JPEG, PNG or WebP inputs and are
  re-encoded to a small JPEG wire payload.

## Reporting

Follow `SUPPORT.md` and use the Torca 0.2 issue template. Suspected security
problems must be reported privately according to `SECURITY.md`.
